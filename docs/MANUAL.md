# Полное руководство по внедрению и эксплуатации `mcpgram` (v0.2)

**`mcpgram`** — self-hosted корпоративный MCP-сервер (Model Context Protocol) для рабочих чатов Telegram на Go.  
Позволяет сотрудникам безопасно подключать ИИ-агентов (Cursor, Claude Desktop, OpenCode, CLI-агенты и др.) к поиску и анализу рабочей переписки — **строго в режиме Read-Only** и с **динамическим контролем прав (RBAC)**, привязанным к реальному членству в Telegram-чатах.

## 1. Как это устроено и почему это безопасно

* **Приватность по умолчанию:** вся база (`SQLite WAL + FTS5`) живёт строго на вашем сервере. Доступа к личным перепискам сотрудников у бота нет. В режиме `pro` эмбеддинги, дайджесты и расшифровка голосовых также работают локально (Ollama + Whisper).
* **Никаких Webhooks и открытых портов в интернет:** бот забирает обновления только по исходящему **Long Polling (`getUpdates`)**. Работает за корпоративным NAT и поддерживает `TELEGRAM_PROXY_URL` (`http`, `https`, `socks5`, `socks5h`).
* **Строго Read-Only:** у ИИ-агента нет инструментов для отправки, редактирования или удаления сообщений в Telegram. Все тексты переписки отдаются в защитной JSON-обёртке (`untrusted_text` + `untrusted_content_notice`) против Indirect Prompt Injection.
* **Токен живёт в MCP-клиенте, а не в LLM:**
  * `Telegram ID` (например, `323291081`) — это неизменяемый публичный идентификатор пользователя (не секрет); по нему бот определяет администраторов (`ADMIN_TG_IDS`) и права в чатах.
  * `Bearer-токен` (`tgmcp_...`) — персональный секретный ключ для HTTP-запросов к `/mcp`. В БД хранится только его **SHA-256 хеш**. Модель никогда не видит токен.
* **Гибридный RBAC (проверка на каждом запросе):**
  * Telegram мгновенно присылает события входа/выхода (`chat_member`), обновляя локальную таблицу `chat_acl`.
  * На каждом MCP-запросе `Authorizer` проверяет свежесть кэша (`RBAC_CACHE_TTL`, по умолчанию 5 мин). Если запись устарела или отсутствует — делается живой `getChatMember` в Telegram.
  * При сетевом сбое срабатывает **fail-closed** (устаревшие права не принимаются, доступ блокируется на уровне SQL).
  * Белый список статусов: `creator`, `administrator`, `member`, а для `restricted` — строго при `is_member = true`.
* **Защита при миграции групп:** при апгрейде обычной группы (`group`) в супергруппу (`supergroup` с `-100...`) история, топики, дайджесты и эмбеддинги автоматически склеиваются под единым внутренним `workspace_chat_id` (UUID).

## 2. Часть 1. Развёртывание с нуля (для администратора)

### 2.1. Требования к серверу и сети

Выберите постоянно работающую машину (24/7 — простой более 24 часов приведёт к потере очереди апдейтов в Telegram):

| Профиль | Состав | Минимум ресурсов | Когда выбирать |
|---|---|---|---|
| **`lite`** | 1 контейнер `mcpgram` (SQLite WAL + FTS5) | 1 vCPU, 512 МБ RAM, 10 ГБ диска | Быстрый старт, мини-ПК/NAS/VPS, текстовый поиск + импорт |
| **`pro`** | `mcpgram` + локальный `ollama` (`bge-m3`, `qwen2.5`) + `faster-whisper-server` | 4+ vCPU, 8–16 ГБ RAM (или GPU / Apple Silicon), 30+ ГБ диска | Ночные дайджесты, семантический гибридный поиск и расшифровка голосовых/кружков полностью локально |

**Сетевой доступ к порту `8080`:**
* **В офисе:** достаточно внутренней локальной сети (`http://tg-mcp.local:8080/mcp`), проброс портов наружу не нужен.
* **Удалённая команда:** корпоративный VPN (Tailscale / WireGuard) **либо** реверс-прокси с обязательным **HTTPS**. Передавать Bearer-токены по открытому HTTP через публичный интернет нельзя.

Пример простого HTTPS-прокси через **Caddy** (`Caddyfile`):
```caddyfile
tg-mcp.company.internal {
    reverse_proxy 127.0.0.1:8080
}
```

### 2.2. Регистрация корпоративного бота в `@BotFather`

> **Критически важно:** создавайте бота строго с **корпоративного сервисного аккаунта** или аккаунта владельца компании. Если зарегистрировать бота на личный аккаунт рядового сотрудника, при его увольнении компания потеряет контроль над токеном.

1. Откройте `@BotFather` в Telegram и отправьте `/newbot`.
2. Задайте отображаемое имя (например, `Company AI Assistant`) и уникальный `@username` с окончанием `bot` (например, `@company_mcp_bot`). Сохраните выданный **`BOT_TOKEN`**.
3. Разрешите добавлять бота в группы:
   * `/setjoingroups` → выберите бота → **Enable**.
4. **Обязательно отключите Privacy Mode** (иначе бот не увидит обычные сообщения в группах):
   * `/setprivacy` → выберите бота → **Disable**.
5. Узнайте свой числовой `Telegram ID`: можно запустить бота с пустым `ADMIN_TG_IDS`, написать ему `/start` в личку — бот сразу ответит вашим числовым ID, после чего впишите его в `.env` и перезапустите сервер.

### 2.3. Вариант А: запуск через Docker Compose (`lite` и `pro`)

Установите Docker и Docker Compose v2, затем выполните:

```bash
mkdir -p /opt/mcpgram && cd /opt/mcpgram
curl -O https://raw.githubusercontent.com/mytischi/mcpgram/main/docker-compose.yml
curl -O https://raw.githubusercontent.com/mytischi/mcpgram/main/.env.example
cp .env.example .env
chmod 600 .env
```

Заполните `.env` (как минимум `BOT_TOKEN` и `ADMIN_TG_IDS`).

#### Запуск профиля `lite` (только ядро + FTS5)
```bash
docker compose --profile lite pull
docker compose --profile lite up -d
docker compose logs -f mcpgram
```

#### Запуск профиля `pro` (ядро + локальный Ollama + локальный Whisper)
1. Включите в `.env` локальные сервисы (обращаются по именам сервисов внутри Docker-сети):
   ```env
   DIGEST_MODE=openai_compatible
   DIGEST_BASE_URL=http://ollama:11434/v1
   DIGEST_MODEL=qwen2.5:7b
   DIGEST_LANGUAGE=ru
   DIGEST_SCHEDULE_HOUR=3
   DIGEST_TIMEZONE=Europe/Moscow

   EMBEDDING_MODE=openai_compatible
   EMBEDDING_BASE_URL=http://ollama:11434/v1
   EMBEDDING_MODEL=bge-m3

   WHISPER_MODE=openai_compatible
   WHISPER_BASE_URL=http://whisper:8000/v1
   WHISPER_MODEL=Systran/faster-whisper-small
   WHISPER_LANGUAGE=ru
   ```
2. Поднимите стек и один раз скачайте модели в Ollama:
   ```bash
   docker compose --profile pro pull
   docker compose --profile pro up -d
   docker compose exec ollama ollama pull bge-m3
   docker compose exec ollama ollama pull qwen2.5:7b
   ```

#### Проверка, что всё поднялось
```bash
curl -s http://127.0.0.1:8080/healthz
# Ожидаемый ответ: {"db":"ok","last_poll_at":"...","polling":"ok","status":"ok"}
```
`/healthz` проверяет не только БД, но и «свежесть» polling-цикла: если бот не получал ответа от Telegram дольше **5 минут**, `/healthz` вернёт `503 Service Unavailable` (`"polling":"stale"`), что удобно подключить к Uptime Kuma / Healthchecks.io.
В логах `mcpgram` должна появиться строка `telegram bot verified ... can_read_all_group_messages=true`. Если там предупреждение про Privacy Mode — вернитесь к шагу 4 раздела 2.2.

### 2.4. Вариант Б: нативный запуск без Docker (macOS / Linux)

Подходит для Apple Silicon (Metal GPU для Ollama и Whisper работает нативно быстрее, чем в Docker) или серверов без Docker.

1. Скачайте готовый статический бинарник со страницы [GitHub Releases](https://github.com/mytischi/mcpgram/releases) (или соберите из исходников `go build -o bin/mcpgram ./cmd/mcpgram`).
2. Создайте `.env` рядом с бинарником, указав локальный путь к БД:
   ```env
   BOT_TOKEN=...
   ADMIN_TG_IDS=323291081
   DATABASE_URL=./data/mcpgram.db
   ```
3. *(Опционально — для локальных дайджестов, семантического поиска и Whisper на macOS Apple Silicon)*:
   ```bash
   brew install ollama whisper-cpp ffmpeg
   ollama serve &
   ollama pull bge-m3
   ollama pull qwen2.5:7b

   mkdir -p ~/.cache/whisper
   curl -fSL -o ~/.cache/whisper/ggml-small.bin \
     https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-small.bin

   whisper-server \
     --host 127.0.0.1 --port 8000 \
     --inference-path /v1/audio/transcriptions \
     --convert --tmp-dir /tmp -l auto \
     -m ~/.cache/whisper/ggml-small.bin &
   ```
   И укажите в `.env` `DIGEST_BASE_URL=http://127.0.0.1:11434/v1`, `EMBEDDING_BASE_URL=http://127.0.0.1:11434/v1`, `WHISPER_BASE_URL=http://127.0.0.1:8000/v1`.
4. Запустите сервер:
   ```bash
   ./mcpgram serve
   ```

### 2.5. Полный справочник переменных `.env`

#### Основные настройки
| Переменная | По умолчанию | Описание |
|---|---|---|
| `BOT_TOKEN` | *(обязательна для `serve`)* | Токен бота от `@BotFather` |
| `ADMIN_TG_IDS` | *(пусто)* | Числовые Telegram ID администраторов через запятую (доступ к `/status`, `/set_policy`, `/digest`, `/revoke_user`) |
| `LISTEN_ADDR` | `:8080` | Адрес и порт HTTP-сервера (`/mcp` и `/healthz`) |
| `DATABASE_URL` | `./data/mcpgram.db` | Путь или URI SQLite (`sqlite:///data/mcpgram.db` в Docker) |
| `DEFAULT_HISTORY_POLICY` | `full_history` | `full_history` — доступ ко всей истории чата (включая до входа); `since_join` — строго сообщения новее `joined_at` |
| `RETENTION_DAYS` | `0` | `0` — хранить сообщения и дайджесты бессрочно; `> 0` (например `90`) — автоудаление старше N дней |
| `TOKEN_TTL_DAYS` | `90` | Срок жизни Bearer-токена в днях (`0` — бессрочный токен до явного отзыва) |
| `RBAC_CACHE_TTL` | `5m` | TTL кэша `chat_acl` до живой перепроверки `getChatMember` (Go-формат: `5m`, `10m`) |
| `IGNORE_TAG` | `#offrecord` | Сообщения с этим тегом (без учёта регистра) не попадают в БД; при добавлении тега редактированием сообщение удаляется |
| `TELEGRAM_PROXY_URL` | *(пусто)* | Опциональный прокси (`http://`, `https://`, `socks5://`, `socks5h://`) для доступа к `api.telegram.org` |
| `LOG_LEVEL` | `info` | Уровень логов: `debug`, `info`, `warn`, `error` |

#### Ночные дайджесты (`get_digests`)
| Переменная | По умолчанию | Описание |
|---|---|---|
| `DIGEST_MODE` | `off` | `off` или `openai_compatible` (Ollama, llama.cpp, vLLM, OpenAI, OpenRouter) |
| `DIGEST_BASE_URL` | *(пусто)* | Базовый `/v1` URL (например `http://127.0.0.1:11434/v1`) |
| `DIGEST_API_KEY` | *(пусто)* | API-ключ (для локального Ollama оставить пустым) |
| `DIGEST_MODEL` | *(пусто)* | Имя модели (например `qwen2.5:7b` или `qwen2.5:3b`) |
| `DIGEST_LANGUAGE` | *(пусто)* | Язык дайджестов (`ru` — нативный русский промпт; пусто = авто по языку переписки) |
| `DIGEST_SCHEDULE_HOUR` | `3` | Час ночного запуска (`0..23`) в `DIGEST_TIMEZONE` |
| `DIGEST_TIMEZONE` | `UTC` | IANA-часовой пояс компании (например `Europe/Moscow`, `Asia/Dubai`) |
| `DIGEST_MIN_MESSAGES` | `3` | Минимум сообщений за день для генерации дайджеста |
| `DIGEST_LOOKBACK_DAYS` | `7` | За сколько прошлых дней догенерировать пропущенные дайджесты |

#### Локальный гибридный поиск (FTS5 + Vector RRF)
| Переменная | По умолчанию | Описание |
|---|---|---|
| `EMBEDDING_MODE` | `off` | `off` (только FTS5) или `openai_compatible` (Ollama, llama.cpp, TEI, FastEmbed, OpenAI) |
| `EMBEDDING_BASE_URL` | *(пусто)* | Базовый `/v1` URL (например `http://127.0.0.1:11434/v1`) |
| `EMBEDDING_API_KEY` | *(пусто)* | Опциональный API-ключ |
| `EMBEDDING_MODEL` | *(пусто)* | Модель эмбеддингов (рекомендуется `bge-m3` для RU/EN) |
| `EMBEDDING_CHUNK_WINDOW_SEC` | `600` | Временное окно склейки сообщений в диалоговый чанк (секунд) |
| `EMBEDDING_CHUNK_MAX_MESSAGES` | `8` | Максимум сообщений в одном диалоговом чанке |
| `EMBEDDING_POLL_INTERVAL` | `2m` | Периодичность фоновой индексации новых сообщений |

#### Транскрибация голосовых и кружков (Whisper)
| Переменная | По умолчанию | Описание |
|---|---|---|
| `WHISPER_MODE` | `off` | `off` или `openai_compatible` (`faster-whisper-server`, `whisper.cpp`, OpenAI Whisper) |
| `WHISPER_BASE_URL` | *(пусто)* | Базовый `/v1` URL (например `http://127.0.0.1:8000/v1`) |
| `WHISPER_API_KEY` | *(пусто)* | Опциональный API-ключ |
| `WHISPER_MODEL` | `whisper-1` | Имя модели (`Systran/faster-whisper-small`, `whisper-1` и т.д.) |
| `WHISPER_LANGUAGE` | *(пусто)* | Код языка (`ru`, `en`, `auto` или пусто для автоопределения) |
| `WHISPER_POLL_INTERVAL` | `30s` | Интервал проверки новых голосовых и кружков |
| `WHISPER_MAX_FILE_BYTES` | `20971520` | Лимит размера скачиваемого в память аудио/видео (по умолчанию 20 МБ — лимит Bot API) |

### 2.6. Добавление бота в рабочие чаты

1. Добавьте бота в нужные рабочие группы Telegram.
2. **Назначьте бота администратором** в каждой группе — без этого Telegram не будет присылать события `chat_member` и проверка прав может не работать.
3. **Снимите с бота все опасные права администратора** (удаление сообщений, бан пользователей, закрепление, изменение профиля группы, добавление админов).
4. Напишите боту в личные сообщения `/status` — убедитесь, что бот видит добавленные чаты со статусом `admin` и `Privacy Mode отключен`.
5. Предупредите коллег (например, в закрепе чата):
   * бот работает строго в режиме чтения;
   * любое сообщение с тегом `#offrecord` полностью игнорируется и не сохраняется в БД (если добавить тег редактированием, оно удалится).

### 2.7. Импорт старой истории из Telegram Desktop (`result.json`)

Telegram Bot API не отдаёт сообщения, отправленные до добавления бота (а также удаляет апдейты из очереди при простое сервера **дольше 24 часов**). Чтобы загрузить старый архив или закрыть пробел без дубликатов:

1. В **Telegram Desktop** *(важно для macOS: используйте именно **Telegram Desktop** с `desktop.telegram.org`, в нативном клиенте из Mac App Store кнопки экспорта нет)* откройте нужный чат → меню (`⋮`) → **Export chat history**.
2. **Снимите все галочки с медиа** (нужен только текст — экспорт займёт 1–2 секунды), в поле **Format** выберите **Machine-readable JSON**, при необходимости задайте диапазон дат **From / To** → нажмите **Export** → получите файл **`result.json`**.
3. Загрузите `result.json` одним из двух способов:

**Способ 1 (без SSH — прямо в личке бота, до 20 МБ ≈ 30–50 тыс. сообщений):**
* Просто перетащите файл `result.json` в **личный чат с ботом** от имени администратора (`ADMIN_TG_IDS`).
* *(Если нужно явно указать Bot API `chat_id`, добавьте его в подпись к файлу, например `-1001234567890`.)*
* Бот сам импортирует сообщения без дублей (учитывая `#offrecord` и `RETENTION_DAYS`), обновит FTS5 и ответит статистикой.

**Способ 2 (через CLI — без лимита 20 МБ):**
```bash
# Нативный бинарник:
./mcpgram import --file /path/to/result.json

# Или внутри Docker-контейнера:
docker compose exec -T mcpgram mcpgram import --file /data/result.json
```
*(Опционально: `--chat-id -1001234567890 --retention-days 0`.)*

4. Если включены семантический поиск и/или дайджесты, они подхватят импортированные сообщения в следующем цикле (или можно запустить сразу вручную: `./mcpgram reindex` и `/digest` / `./mcpgram digest`).

## 3. Часть 2. Подключение сотрудника (памятка для команды)

Настройка выполняется **один раз** за 2–3 минуты. После этого доступ ко всем рабочим чатам синхронизируется автоматически с Telegram.

### Шаг 1. Проверьте сеть
Подключитесь к офисной сети или включите корпоративный VPN (Tailscale / WireGuard), чтобы был доступен адрес сервера (например, `http://tg-mcp.local:8080/mcp` или `https://tg-mcp.company.internal/mcp`).

### Шаг 2. Получите персональный Bearer-токен
1. Откройте **личный чат** с корпоративным ботом (например, `@company_mcp_bot`).
2. Отправьте команду:
   ```text
   /auth
   ```
3. Бот проверит, что вы состоите хотя бы в одном рабочем чате компании, и выдаст персональный ключ вида `tgmcp_9f8a7b6c...`.

> **Главное правило безопасности:** никогда не вставляйте токен в обычный чат с нейросетью и не просите ИИ «запомнить мой ключ». Токен прописывается **только** в техническом файле конфигурации MCP-клиента.

### Шаг 3. Пропишите сервер в вашем ИИ-клиенте

#### Cursor / OpenCode / Windsurf (`mcp.json`)
```json
{
```

## 4. Часть 3. Администрирование и эксплуатация (Day-2)

### Справочник команд бота (в личных сообщениях)
| Команда | Кто может вызвать | Назначение |
|---|---|---|
| `/start` / `/help` | Любой | Показывает ваш числовой `Telegram ID` и список команд |
| `/auth` | Участники чатов и админы | Выдаёт новый Bearer-токен (старый сразу аннулируется) |
| `/status` | `ADMIN_TG_IDS` | Диагностика: бот, Privacy Mode, статус дайджестов/поиска/Whisper, список чатов с их `ws=...` |
| `/set_policy <ws_id> <full_history\|since_join\|default>` | `ADMIN_TG_IDS` | Точечно переопределяет политику истории для конкретного чата (например, закрыть прошлый архив в чате с подрядчиком) |
| `/digest [YYYY-MM-DD\|today]` | `ADMIN_TG_IDS` | Вручную запускает генерацию дайджестов (за `DIGEST_LOOKBACK_DAYS` или за конкретный день) |
| `/revoke_user <telegram_user_id>` | `ADMIN_TG_IDS` | Мгновенно отзывает все активные токены сотрудника |
| *(отправка файла `result.json`)* | `ADMIN_TG_IDS` | Импортирует JSON-экспорт из Telegram Desktop прямо из лички бота без SSH (до 20 МБ, без дублей) |

### Авто-алерт при длительном простое (> 20 часов)
При каждом запуске `mcpgram` проверяет время последнего успешного опроса Telegram (`bots.last_poll_at`):
* **Простой < 24 часов:** Telegram сам отдаёт все накопившиеся апдейты, сообщения не теряются.
* **Простой ≥ 20 часов:** бот автоматически присылает всем `ADMIN_TG_IDS` в личку предупреждение с точным интервалом простоя и инструкцией, как за 30 секунд закрыть возможный пробел отправкой `result.json` в личку бота.

### Справочник CLI-команд
```bash
mcpgram serve                         # Запуск основного сервера + всех включённых воркеров
mcpgram import --file result.json     # Импорт JSON-экспорта из Telegram Desktop
mcpgram digest [--date YYYY-MM-DD]    # Генерация дайджестов (--today, --chat-id, --force)
mcpgram reindex                       # Построение/обновление семантических эмбеддингов
mcpgram version                       # Версия бинарника
```

### Типовые сценарии Day-2

**Новый сотрудник / перевод в другой проект**
* Действий администратора `mcpgram` не требуется: добавьте человека в нужный Telegram-чат → событие `chat_member` автоматически откроет доступ.
* Если это чат с внешним подрядчиком и ему нельзя видеть старую переписку — выполните `/status`, скопируйте `ws=<uuid>` чата и отправьте боту:
  ```text
  /set_policy <uuid> since_join
  ```

**Увольнение сотрудника или утеря ноутбука**
1. Удалите сотрудника из рабочих чатов Telegram (доступ закроется сразу по `chat_member`, максимум в пределах `RBAC_CACHE_TTL` = 5 мин).
2. Отправьте боту команду глобального отзыва токенов (защищает от «забытых» архивных чатов):
   ```text
   /revoke_user <telegram_user_id>
   ```
3. Отключите сотрудника от корпоративного VPN / Tailscale.

**Компрометация ключа самим сотрудником**
* Сотрудник просто отправляет боту `/auth` ещё раз — старый токен аннулируется мгновенно, взамен выдаётся новый.

**Безопасный бэкап SQLite (в режиме WAL)**
Не копируйте `.db` простым `cp` во время записи без WAL-чекпоинта — используйте встроенный бэкап SQLite:
```bash
# Нативно:
sqlite3 ./data/mcpgram.db ".backup /backups/mcpgram-$(date +%F).db"

# Или через остановку на 2 секунды / бэкап Docker Volume:
docker compose stop mcpgram
docker run --rm -v mcpgram_mcpgram_data:/data -v /backups:/backup alpine \
  tar czf /backup/mcpgram-$(date +%F).tar.gz -C /data .
docker compose start mcpgram
```

**Обновление версии**
Все данные хранятся в Docker Volume (`mcpgram_data`), миграции БД применяются автоматически при старте:
```bash
cd /opt/mcpgram
docker compose --profile lite pull   # или --profile pro
docker compose --profile lite up -d
```

## 5. Часть 4. Диагностика и решение проблем

| Симптом | Вероятная причина | Решение |
|---|---|---|
| Бот в группе, но новые сообщения не сохраняются | Включён Privacy Mode или бот не админ | Вызовите `/status`; отключите `/setprivacy` в `@BotFather` и выдайте боту статус админа в чате |
| Бот отклоняет `/auth` («Доступ отклонён») | Пользователь не состоит ни в одном отслеживаемом чате и не указан в `ADMIN_TG_IDS` | Добавьте сотрудника в корпоративный чат с ботом (и убедитесь, что бот в этом чате админ), затем повторите `/auth` |
| Клиент получает `401 Unauthorized` | Неверный, отозванный (`/revoke_user`) или просроченный (`TOKEN_TTL_DAYS`) Bearer-токен | Перепроверьте `Authorization: Bearer ...` в конфиге клиента или перевыпустите ключ через `/auth` |
| Клиент получает `forbidden` по чату | Пользователь не состоит в чате, вышел со статусом `restricted (is_member=false)` или сработал fail-closed при обрыве связи с Telegram | Проверьте состав участников в Telegram и доступность `api.telegram.org` в логах сервера |
| Не видны старые сообщения чата | Включено `since_join` (глобально или через `/set_policy`), либо сообщения были до добавления бота | Проверьте политику в `/status`; для старой истории сделайте разовый `mcpgram import --file result.json` |
| `get_digests` возвращает пустой список | `DIGEST_MODE=off`, за день было меньше `DIGEST_MIN_MESSAGES` сообщений, или ещё не наступил `DIGEST_SCHEDULE_HOUR` | Проверьте `/status`; проверьте генерацию вручную через `/digest today` или `./mcpgram digest --today --force` |
| Дайджесты приходят на английском вместо русского | Небольшая локальная LLM (например 3B) следует языку базового промпта | Укажите `DIGEST_LANGUAGE=ru` в `.env` и/или используйте `qwen2.5:7b` |
| Голосовые не расшифровываются | `WHISPER_MODE=off`, нет `ffmpeg` у `whisper-server` (`--convert`) или файл > 20 МБ | Проверьте `/status`, логи `mcpgram` и доступность `WHISPER_BASE_URL/audio/transcriptions` |
| Ошибки подключения к `api.telegram.org` | Блокировка или корпоративный файрвол | Укажите `TELEGRAM_PROXY_URL=socks5://...` или `http://...` в `.env` и перезапустите сервер |
| После включения Forum Topics пропал чат | Группа мигрировала в супергруппу (`-100...`) | `mcpgram` обрабатывает `migrate_to_chat_id` автоматически; проверьте `/status` — должен остаться прежний `ws=` |
| Пропали сообщения после простоя > 24 часов | Telegram хранит очередь `getUpdates` только 24 часа | Бот сам пришлёт алерт админам при простое ≥ 20 ч; выгрузите пропущенные дни в JSON из Telegram Desktop и киньте `result.json` в личку бота |
| `/healthz` возвращает `503` (`polling: stale`) | Потеряна связь с `api.telegram.org` или завис polling (> 5 мин) | Проверьте логи `mcpgram`, сетевой доступ / `TELEGRAM_PROXY_URL` и перезапустите контейнер |
